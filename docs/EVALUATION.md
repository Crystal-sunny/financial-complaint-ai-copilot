# 评测口径与结果边界

## 三层验证

金融 Agent 的“回答通顺”不能证明安全。项目将验证拆分为代码级安全、应用级护栏和模型级泛化。

| 层级 | 目的 | 是否调用模型 |
| --- | --- | --- |
| 离线安全与契约测试 | 验证密钥隔离、数据外发、结构化输出、工具权限、审批和时间边界 | 否 |
| 真实代码护栏 | 验证编排器、安全校验器与只读工具在边界输入下的行为 | 否 |
| 冻结候选集 | 验证真实 GLM 在新合成组合样本上的端到端表现 | 是 |

## 冻结流程

1. 编写新的合成、脱敏案例及评分条件；
2. 用 SHA-256 锁定数据集和批次；
3. 在首次模型调用前提交冻结版本；
4. 每个案例依次运行三个 Agent，不自动重试、不允许稳定模式回退；
5. 保存安全摘要、校验结果和 Token 元数据，不保存供应商原始响应；
6. 保留失败样本，作为下一轮开发回归或新冻结集的设计输入。

## V6 泛化验证

| 指标 | 结果 |
| --- | --- |
| 数据集 | 12 个新合成组合样本 |
| 覆盖 | 多候选扣款、计划缺失、账务时序、规则失效、跨客户关系、安全边界、提示注入 |
| 端到端完成 | 12 / 12 |
| 通过结构化校验的 Agent 阶段 | 36 / 36 |
| 机器通过 | 9 / 12（75.0%） |
| 已返回校验元数据的 Token | 输入 113,582；输出 54,116 |

V6 的 3 个差异未被重跑或改写答案，涉及时序证据门、完成冲正的最终归属，以及“高风险但未明确否认授权”的升级边界。它说明模型能够完成受约束流程，也说明业务口径仍需要继续由应用层规则和新的冻结集验证。

公开仓库只保留当前 V6 冻结样本、SHA 锁与[脱敏计分卡](../evals/model-candidates-v6-scorecard.md)。旧轮次开发数据、原始供应商响应及逐次调试报告不进入当前公开版本。

## 不应从结果推导什么

- 内部合成集成绩不是真实金融客诉准确率；
- 开发方编写的样本不是第三方独立基准；
- 端到端完成或 JSON 合法不等于业务正确；
- 本项目不能用于真实资金、信贷、支付或合规决策。
